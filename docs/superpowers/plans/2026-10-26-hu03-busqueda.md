**Goal:** Add the HU-03 #35 GET lookup that uses the already validated `url_busqueda` and passes the API response to #36.

**Architecture:** Extend the inactive #34 workflow export with one authenticated HTTP Request node. **Spec:** `specs/03-abonos-distancia.md`, steps 2–4; project conventions in `AGENTS.md` and domain terms in `docs/ontologia.md`.

## Global Constraints

- Use `http://tienda:8000` from inside n8n and attach `X-API-Key` via the `API Tienda` Header Auth credential.
- For explicit IDs use the URL already produced by #34; do not fall back to a name query on 404.
- For name lookups use `estado=activo` and the conservative query already produced by #34; do not send the full payer name.
- Do not add writes, email sends, or activate/publish the workflow in #35.
- Preserve workflow 08 as the technical error handler reference; an instance may need to select its local copy.

## Review Focus

- Explicit ID and name query must both use the exact upstream `url_busqueda`; test that no URL is reconstructed from untrusted fields.
- Empty candidate result must still reach #36 for a review decision; test that the lookup output is not dropped.
- HTTP 404 must remain distinguishable for explicit-ID review; test the configured full response.
- HTTP 401/5xx must remain distinguishable for #36, while network failures stop the workflow and invoke #08; test the response options and absence of an error-continuation override.
- No payment or email side effect may be introduced; test the workflow contains only the GET request beyond #34.
